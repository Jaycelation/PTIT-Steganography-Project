# dc-ac-drift-extract

This Labtainer lab uses the `dc-ac-combined` challenge as a first clean conversion target.

You will inspect a stego MP4, run the DC/AC extraction pipeline, produce an answer file, and report simple extraction metrics. The underlying model is a local frame-DCT simulation in Python. It is not codec-level MPEG bitstream editing.

## Files

- `output/stego.mp4`: public stego video.
- `output/public_config.json`: public extraction parameters.
- `solve.py`: base extractor.
- `src/`: DCT, video I/O, extraction helpers.
- `tools/`: Labtainer checkwork helpers.
- `work/`: generated by your commands.

## Required Steps

Run commands from this directory:

```bash
cd ~/dc-ac-drift-extract
```

Inspect video metadata:

```bash
python3 tools/check_video_metadata.py
```

Run the DC/AC extractor:

```bash
python3 tools/run_dc_ac_extract.py
```

Report metrics:

```bash
python3 tools/report_metrics.py
```

Expected generated files:

- `work/video_metadata.txt`
- `work/extract.log`
- `work/answer.txt`
- `work/answer_status.txt`
- `work/answer.sha256`
- `work/metrics.json`

## Checkwork Markers

- `VIDEO_METADATA_OK`
- `DC_AC_EXTRACT_OK`
- `ANSWER_FILE_CREATED`
- `METRICS_OK`

The recovered flag itself is not published in this guide. Labtainer grading checks the hash of your answer.

## Drift Compensation Context

The full drift-compensation lab will use `drift-compensation-basic`. In this first lab, focus on understanding how DC coefficients can carry a header and AC midband coefficients can carry payload bits. The metrics step records frame count, dimensions, and coefficient capacity so you can reason about how drift or re-encoding would affect extraction reliability.
